# Data Governance — Agent Failure Atlas 2026 (v2)

**This is synthetic benchmark data.** Every row in every table — including
the new `evidence.csv` table — is produced by a seeded, deterministic
Python pipeline. It does not represent real production agent logs, real
user data, or real model API output. Read this document before treating
any number in this dataset as a measurement of a real system.

> **The benchmark uses synthetic evidence and synthetic trajectories; it
> is intended for controlled research and educational experimentation
> rather than as a substitute for real production agent logs.**

## Data origin

100% synthetically generated by `src/generation/generate_data.py`, a
deterministic, seeded Python pipeline. No real user data, no scraped
content, no proprietary corpora, and no live calls to any model API were
used to produce this dataset. See `docs/methodology.md` for the full
generation process and `docs/reproducibility.md` for exact regeneration
instructions.

## Synthetic vs. real data

**All data in this release is synthetic.** Task descriptions are
templated from a fixed set of domains and topics; trajectory content (tool
inputs/outputs, observations) is templated with randomized arguments,
result sizes, and non-fatal noise; failure and recovery events — including
multi-failure sequences and cascades — are injected by a documented
probabilistic process (`docs/methodology.md`); `evidence.csv` claim/support
relationships are likewise generated, not extracted from real retrieved
documents. Nothing in this dataset represents a real user's data, a real
deployed agent's transcript, or a real model provider's actual behavior.
`agents.execution_mode` is set to the constant `synthetic_simulation` on
every row specifically to make this machine-checkable, not just documented
in prose — there is no `real_model_execution` value anywhere in this
release.

## Privacy considerations

There is no personal information, no real user data, and nothing to
anonymize, because nothing in the dataset originates from a real person or
real system. No PII risk exists in this release.

## What is deliberately NOT published

- **No hidden chain-of-thought.** `trajectory_steps.observation` records a
  short, concise, *observable* description of what happened at a step
  (e.g. "Step 3 (execution) completed as expected") and
  `decision_category` records the *kind* of decision made — not a private
  reasoning trace. This is a deliberate design choice, not an omission:
  publishing chain-of-thought-style text would (a) misrepresent this
  simulated dataset as if it captured real model internals, and (b) is
  explicitly out of scope per this project's non-negotiable requirements.
- No API keys, credentials, or secrets are referenced anywhere in the
  generation code or data (the "API" tool category in `tools.csv` is a
  simulated tool catalogue entry, not a real credentialed integration).

## Intended use

- Research into agent failure taxonomy, recovery strategy effectiveness,
  and trajectory-level analysis methods.
- Student and educational projects: classification, EDA, relational-data
  practice, taxonomy design.
- Benchmarking analysis *methods* (e.g. "does this failure-prediction
  approach work on structured trajectory data") rather than benchmarking
  real agents against each other.

## Prohibited / misleading interpretations

- **Do not** cite this dataset's failure rates, recovery success rates, or
  model comparisons as measurements of any real model provider's or
  framework's actual reliability. The `agents.csv` model/provider labels
  are simulation identifiers (see `docs/methodology.md`), not results from
  running real models.
- **Do not** treat `grounding_score` as a measurement against real-world
  source text. v2 computes it genuinely from `evidence.csv`
  (`mean(supports_claim)`), which is a real improvement over v1's sampled
  proxy, but the evidence corpus itself is simulated — there are no real
  retrieved documents behind it. Read it as "groundedness under this
  dataset's simulated evidence model" (see `docs/methodology.md`,
  "Evaluation metrics — exact computation").
- **Do not** treat `agents.capability_tier` as a real capability ranking
  of the named model families — it is a labeled simulation parameter used
  to modulate synthetic failure/recovery probability (see
  `docs/methodology.md`, "Feature-driven failure probability"), not a
  benchmark result.
- **Do not** present this dataset as containing real chain-of-thought or
  real model transcripts of any kind.

## Known limitations

See `docs/methodology.md` ("Known limitations of the methodology") and the
README's Limitations section for the full, honest list, including:
step content that is randomized-from-templates rather than naturalistic
free text, a hand-curated (not learned) failure-cascade edge list, a
simulated (not real-document-backed) evidence corpus, and an explicit
`MAX_FAILURES_PER_RUN=4` safety cap.
