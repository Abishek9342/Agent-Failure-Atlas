## Kaggle Discussion

**Title:** What Is the Hardest AI-Agent Failure to Recover From?

**Post:**

I put together **Agent Failure Atlas 2026** because most agent datasets
I could find stop at prompt → response → pass/fail. That tells you
*whether* an agent succeeded, but not *how* it got there, *where* it
broke, or *whether it recovered*. The dataset tracks the full lifecycle —
task, tool calls, decisions, diagnosed failures (a run can have several,
and they can cascade into one another), recovery attempts, and outcome —
all linked by consistent IDs across a 10-table relational schema.

It's a synthetic, fully reproducible benchmark: 1,400 tasks, 3,336 agent
trajectories, 43,477 trajectory steps, 3,802 failure events, and 4,334
recovery attempts, generated by one seeded pipeline. The taxonomy covers
30 failure types across 8 categories with a documented severity rubric,
and 9 recovery strategies — including cases where a failure gets more
than one recovery attempt (later attempts succeed less often, a measured
effect, not an assumption).

One design decision I'd specifically like feedback on: a handful of
failure types (`tool_loop`, `false_verification`, `unsupported_conclusion`,
`unauthorized_action`, `hallucinated_result`, `claimed_success_after_failure`)
are architecturally unrecoverable in this dataset — the agent's own
signal about its state is untrustworthy in exactly these cases, so no
recovery strategy has anything reliable to act on.

**Questions for the community:**
- Which failure category do you think is hardest to recover from in
  practice — does it match what's marked unrecoverable here?
- What failure type have you actually hit that doesn't map cleanly onto
  this taxonomy?
- What additional fields would make a benchmark like this more useful for
  your own work?

Would love for researchers, students, and engineers working on agent
reliability to try it out and tell me where it breaks.

## LinkedIn

Most AI agent benchmarks measure whether an agent succeeded. They don't
tell you *how* it got there, *where* it broke, or *whether it recovered*.

I built **Agent Failure Atlas 2026** to fill that gap — a structured,
relational dataset of 3,336 multi-step AI-agent trajectories, each
capable of containing multiple, even cascading, failures, every one
diagnosed against a documented taxonomy and paired with its own recovery
attempt(s).

A few things I think are genuinely useful here:
→ Failures can cause other failures — modeled as a resolvable graph
  (`parent_failure_id`), not just narrative description
→ Recovery is first-class data — including repeated attempts with
  different strategies, and yes, later attempts succeed less often
→ A real, non-trivial ML benchmark: predicting failure from
  pre-completion features alone reaches ROC-AUC 0.838 without any label
  leakage (fully documented, including exactly how leakage was avoided)

It's synthetic and fully reproducible — one seeded pipeline, 107
automated validation checks, 13 tests, all passing. I built it that way
deliberately: full transparency over claiming it's something it's not.

Three notebooks included: an exploratory analysis, the failure-prediction
baseline, and a recovery-strategy deep dive.

Link in comments. Would genuinely appreciate feedback from anyone working
on agent evaluation or reliability.

## Reddit (r/MachineLearning or r/datasets — check each subreddit's self-promotion rules before posting)

**Title:** [D] Agent Failure Atlas 2026 — a relational benchmark for AI-agent failure, cascades, and recovery (synthetic, reproducible)

Most public agent datasets are prompt→response→pass/fail. I wanted
something that captures the mechanics: where an agent failed, why, how
failures can cascade into each other, and whether recovery worked — so I
built Agent Failure Atlas 2026.

It's a synthetic, seeded, fully reproducible dataset — 3,336 trajectories,
43,477 steps, 3,802 failure events (a run can have several, and they can
cascade — modeled as a resolvable FK graph, not just narrative), 4,334
recovery attempts (including repeated attempts on the same failure, which
measurably succeed less often on the 2nd try).

Honesty check up front: it's synthetic, not real agent transcripts —
documented explicitly, not buried. The upside is full reproducibility
(107/107 validation checks, deterministic generation) and internally
consistent labels, which real-transcript datasets in this space generally
can't offer.

Also includes an ML baseline notebook — predicting failure from
pre-completion features reaches ROC-AUC 0.838, with an explicit writeup
of how label leakage was avoided (whole-run features like tool_call_count
are excluded since they're inflated by recovery steps; features are built
only from the pre-failure step prefix).

Genuinely interested in feedback, especially on the failure taxonomy and
what's missing.
